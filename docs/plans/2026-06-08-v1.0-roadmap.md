# fissible/attest — v1.0 Roadmap

> Worker repo: `fissible/attest`. Status source of truth for the v1.0 push. Stateless —
> readable in a fresh session with no prior context.

**Goal:** Take core `fissible/attest` from `v0.4.2-alpha` to a stable `v1.0.0` — a code-quality
and API-stability milestone for the fissible suite's own use, **not** gated on external adoption.

**Effort key:** XS (<1h) · S (1–2h) · M (~half day) · L (~1 day) · XL (2–3 days).

---

## Decisions locked (2026-06-08)

1. **Path A — local integrity is the stable v1.0 surface; anchoring ships but is labeled
   experimental.** The sign/chain/verify core, stores, bundles, and CLI are frozen under semver
   at 1.0. The OpenTimestamps/Bitcoin anchoring subsystem remains usable but is explicitly
   *excluded* from the stability guarantee and may change in a 1.x minor; it graduates once it
   has live-network validation. Rationale: anchoring depends on external services (OTS calendars,
   Bitcoin) and has only been exercised against mocked HTTP, not soaked end-to-end. Let a real
   use case pull it to stable later.
2. **Binary canonical wrapper switches to `$binary`.** Replace `{"_attest_binary": "<base64>"}`
   with `{"$binary": "<base64>"}` now, while the format is still alpha and cheap to change, and
   reserve the key in `PayloadValidator`. Accepted consequence: any alpha-era envelope that
   contains a binary blob will no longer verify (its signature was computed over the old
   canonical bytes) — see Risks.

## Tasks

### T1 — Switch binary wrapper to `$binary` and reserve the key · **S** · deps: none · [#2](https://github.com/fissible/attest/issues/2)

The canonical format is locked at 1.0, so settle the sentinel now.

- `src/Envelope/PayloadValidator.php:101` — emit `['$binary' => $value->base64]` instead of
  `['_attest_binary' => ...]`.
- Add a **reservation guard** in `PayloadValidator`: reject a user payload that contains a
  `$binary`-shaped object (single key `$binary` with a string value) anywhere it isn't a real
  `Binary`, so user data can never be mistaken for the sentinel. Define "binary blob" precisely
  as an object with exactly the key `$binary` whose value is base64.
- `src/Envelope/Binary.php:10` — update the docblock to the new canonical form.
- Tests: `tests/Envelope/BinaryRoundTripTest.php`, `tests/Envelope/PayloadValidatorTest.php` —
  update expected canonical bytes; add a collision-rejection test.
- **Done when:** round-trip + collision tests pass; no `_attest_binary` left in `src/` or
  `tests/` (`grep -rn _attest_binary src tests` is empty).

### T2 — Optional fsync on FileChainStore · **S** · deps: none · [#3](https://github.com/fissible/attest/issues/3)

The "PHP has no portable fsync" premise is outdated — PHP 8.1+ ships `fsync()`/`fdatasync()`
and core requires `^8.2`.

- `src/Chain/FileChainStore.php` — add a constructor flag (e.g. `bool $fsync = false`); when
  enabled, call `fsync($dataFp)` after `fflush()` in `append()` (and consider an fsync of the
  containing directory after the meta/index `rename()`s for full durability).
- Replace the misleading comment at `FileChainStore.php:69` and update the CHANGELOG
  durability note (currently `CHANGELOG.md:87`).
- **Default off** to preserve append throughput; document the trade-off (fsync = power-loss
  durable but slower per append).
- Tests: assert append still succeeds with `fsync: true`. Note in the test/docs that true
  power-loss durability cannot be unit-tested — this is the IO-validation caveat, not a unit
  assertion.
- **Done when:** flag wired, comment + CHANGELOG corrected, suite green.

## Risks / coordination

- **Binary format break (T1).** A signed envelope's signature is computed over its canonical
  bytes, which include the wrapper key. Switching `_attest_binary` → `$binary` means any
  pre-existing alpha-era envelope carrying a binary blob will fail verification — there is no
  transparent migration (you can't re-canonicalize signed bytes). Acceptable under alpha and the
  locked decision, but **confirm no fissible chain (esp. Station) holds binary-bearing envelopes
  that must survive**, or accept they're abandoned. Most chains likely use no `Binary` payloads.
- **Cross-repo ripple (T5, T6 downstream).** Spec lives in `station`; the adapter
  (`attest-laravel`) pins `fissible/attest ^0.4.0-alpha` and will need its own constraint bump +
  release after core 1.0. Neither blocks the core cut.
- **Anchoring graduation is deferred, not free.** Path A is honest only if the README/spec/docs
  consistently mark anchoring experimental. T4 is what makes the 1.0 credible — don't skip it.
